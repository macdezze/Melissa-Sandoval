01 · Contexto

El caso.

Nova Studio es una empresa ficticia utilizada para demostrar cómo organizaría administrativamente un pequeño negocio trabajando como asistente virtual.

01

Empresa

Estudio creativo con 4 integrantes que trabaja con clientes de diseño, redes sociales, fotografía y contenido digital.

02

Situación

El crecimiento del negocio generó información repartida entre correos, mensajes, documentos y distintas hojas de cálculo.

03

Objetivo

Crear un sistema centralizado que permitiera encontrar rápidamente información y mantener control de tareas, clientes y pagos.

02 · Diagnóstico

¿Qué estaba fallando?

Antes de crear una solución, se identificaron los principales problemas administrativos.

!

Información dispersa

Los datos de clientes estaban repartidos entre mensajes, correos electrónicos, notas y documentos diferentes.

!

Tareas sin seguimiento

No existía un registro centralizado para saber qué tarea estaba pendiente, quién debía realizarla o cuándo vencía.

!

Pagos poco visibles

Era necesario revisar conversaciones antiguas para saber qué clientes habían pagado y cuáles tenían facturas pendientes.

!

Archivos desordenados

Los proyectos utilizaban nombres distintos y no existía una estructura común para almacenar contratos, briefs y entregas.

03 · Solución

Un sistema. No más caos.

La propuesta se dividió en cinco áreas que podían mantenerse fácilmente después de implementadas.

Base de datos de clientes

01

Centralización de nombre, empresa, correo, teléfono, servicio contratado, fecha de inicio, estado y próximos pasos.

Seguimiento de tareas

02

Creación de un sistema donde cada tarea posee responsable, prioridad, fecha límite y estado.

Control de pagos

03

Registro de facturas emitidas, monto, fecha de vencimiento, estado y fecha efectiva de pago.

Organización documental

04

Diseño de estructura de carpetas y sistema estándar de nombres para encontrar cualquier documento en pocos segundos.

Procedimientos administrativos

05

Creación de procesos sencillos para incorporar clientes, registrar tareas, gestionar pagos y cerrar proyectos.

07 · Procedimiento

Flujo para nuevos clientes.

Se creó un procedimiento simple para evitar que cada nuevo proyecto comenzara desde cero.

1
Registro

Agregar cliente a la base de datos.

2
Carpeta

Crear estructura documental estándar.

3
Brief

Registrar necesidades, fechas y objetivos.

4
Tareas

Crear actividades, responsables y plazos.

5
Seguimiento

Actualizar proyecto hasta su cierre.

08 · Documentos

Plantillas reutilizables.

Para reducir trabajo repetitivo se diseñaron modelos administrativos que pueden reutilizarse con cada cliente.

📋

Brief de cliente

Documento para recopilar información inicial, objetivos, alcance, fechas y responsables.

✉️

Email de bienvenida

Plantilla de correo para enviar instrucciones, documentos necesarios y próximos pasos.

💰

Registro de pagos

Hoja de control con factura, monto, vencimiento, estado y fecha de pago.

📆

Agenda semanal

Resumen de reuniones, entregas y tareas prioritarias para cada semana.

✅

Checklist de cierre

Lista para verificar entregables, facturas, archivos y documentos antes de cerrar un proyecto.

📊

Reporte mensual

Resumen administrativo con proyectos activos, pendientes y pagos.

¿Qué demuestra este proyecto?

Este caso fue desarrollado como proyecto demostrativo para representar cómo puedo abordar tareas de asistencia virtual, data entry y organización administrativa.

El proyecto demuestra capacidad para analizar información desordenada, crear sistemas claros, estructurar documentos, mantener bases de datos y diseñar procesos fáciles de seguir.
